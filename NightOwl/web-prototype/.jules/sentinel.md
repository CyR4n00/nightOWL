## 2025-07-15 - [PostgREST Injection via String Interpolation in .or()]
**Vulnerability:** A query in `PrivateChatView.tsx` used string interpolation within a Supabase `.or()` clause: `.or(\`and(sender_id.eq.${userId},receiver_id.eq.${friend.id})...\`)`. This created a critical PostgREST injection risk where malicious user IDs containing `,` or `)` could manipulate the resulting filter string and bypass intended authorization limits.
**Learning:** String interpolation should never be used to dynamically build Supabase/PostgREST query parameters. While standard values are escaped by the client, directly injecting values into the raw filter string circumvents this safety mechanism. Attempting to fix this with `.in()` clauses can lead to Cartesian product logic bugs (matching self-messages).
**Prevention:** Always use separate query builder methods (e.g., `.eq()`) directly, utilizing `Promise.all()` to run multiple safe queries concurrently and combining the results client-side when complex `OR` logic cannot be safely parameterized natively.
