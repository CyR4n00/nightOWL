## 2024-06-17 - Unmemoized `Math.random` in Render Loop
**Learning:** Generating randomized values (e.g., using `Math.random()`) for static or visual elements (like CSS position or size) within the main render loop of React components causes severe UI thrashing across state re-renders (e.g., auth session changes). This leads to unpredictable and frequent DOM reflows and visually jarring re-randomizations.
**Action:** Always wrap the generation logic in a `useMemo` hook with an appropriate dependency array so that the randomized static elements are calculated exactly once (or as needed) and preserve their values across unrelated state changes.
## 2024-06-18 - Unmemoized List Items Coupled with Input State
**Learning:** In `HomeView.tsx`, the post list rendering was coupled with the text input state (`inputText`) within the same component. Because the feed items were mapped directly in the render body without memoization, every keystroke in the input triggered a full re-render of the entire feed list, resulting in O(n) rendering complexity on keystrokes and sluggish input performance.
**Action:** Extract list items into separate components (e.g., `PostItem`) and wrap them with `React.memo()`. This ensures that updating state isolated to other parts of the view (like a controlled text input) doesn't force unnecessary cascading re-renders of the entire list.
