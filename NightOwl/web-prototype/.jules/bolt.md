## 2026-06-23 - Handle Type Definition Gaps During Prototyping
**Learning:** For fast UI prototyping when backend schema definitions or API responses are unavailable or incomplete, attempting to strictly type Supabase relational payloads with \`Record<string, unknown>\` can inadvertently break React JSX template rendering (e.g. \`friend.name\` throws type errors) and cause cascading compilation failures.
**Action:** When iterating rapidly on pure UI changes without robust type definitions, prioritize a working build. It is acceptable to temporarily use \`any\` types combined with targeted \`/* eslint-disable @typescript-eslint/no-explicit-any */\` directives to unblock UI verification, rather than spending excessive cycles untangling nested typing complexities before the backend is finalized.
