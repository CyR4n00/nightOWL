## 2025-02-09 - PostgREST String Interpolation Injection Risk\n**Vulnerability:** String interpolation in Supabase PostgREST `.or()` filters (e.g., `.or(`sender_id.eq.${userId}...`)`).\n**Learning:** This pattern allowed users to potentially inject arbitrary filter conditions by crafting a payload with escaped parentheses, bypassing intended row-level isolation logic in the backend.\n**Prevention:** Never use string interpolation for dynamically generated PostgREST queries. Always use explicit, parameterized `.eq()` or `.in()` matchers natively provided by the Supabase client. When complex OR logic involves multiple combinations, execute independent parameterized queries concurrently via `Promise.all()` and combine/sort the data client-side.
